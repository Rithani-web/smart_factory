# Implementation Plan: MVP Production Event Lifecycle

**Branch**: `001-mvp-event-lifecycle` | **Date**: 2026-10-07 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-mvp-event-lifecycle/spec.md`

## Summary

Build the MVP core of the Smart Factory Production Automation System: authenticated,
role-based users (Admin / Technician / Viewer) report production events, which are
auto-assigned to an on-duty technician and notified by email, then walked through
acknowledgement and resolution with a full lifecycle history. Technical approach: a
TypeScript monorepo — Express + Prisma backend serving a REST API, React + Vite +
Tailwind frontend consuming it through shared types, PostgreSQL on Neon as storage,
JWT sessions in HTTP-only cookies, Resend for email — implemented strictly through the
Spec Kit task workflow.

## Technical Context

**Language/Version**: TypeScript 5.x on Node.js 20 LTS (ESM)

**Primary Dependencies**: Express, Prisma (+ @prisma/client), jsonwebtoken, bcrypt,
Resend SDK (backend); React, Vite, Tailwind CSS (frontend); npm workspaces monorepo

**Storage**: PostgreSQL hosted on Neon (pooled connection for the app, direct for
migrations); Prisma schema is the single source of truth (Constitution IV)

**Testing**: Vitest (test runner — decision in research.md) + Supertest (HTTP
contract tests); fake mailer injected in tests (no network)

**Target Platform**: Web — Node.js API server (localhost:3000 dev) + browser SPA
(localhost:5173 dev)

**Project Type**: Web application monorepo (`backend/`, `frontend/`, `shared/`)

**Performance Goals**: Assignment happens synchronously at event creation (SC-002:
Assigned ≤1 min after creation); notification email dispatched immediately, delivered
≤5 min under normal operation (SC-003); p95 API response < 500 ms on dev hardware

**Constraints**: All secrets in `.env` only (never committed); every permission check
server-side (Constitution II); e2e shared TypeScript types (III); one schema source of
truth (IV); secure-by-default auth (V); no technologies beyond the fixed stack (VI)

**Scale/Scope**: Single factory organization; dozens of users; low event volume
(internal MVP). Scope = spec/001 only — rosters/escalation rules arrive in spec/002.

### Source Code (repository root)

```text
backend/
├── prisma/
│   ├── schema.prisma        # SINGLE source of truth for all data (Constitution IV)
│   └── migrations/          # generated by Prisma — never hand-written
├── src/
│   ├── auth/                # login, refresh, logout, first-password-change, RBAC middleware
│   ├── users/               # admin user provisioning (temp password), user list
│   ├── events/              # create (auto-assign), list, detail, acknowledge, resolve, reassign
│   ├── roster/              # minimal duty roster: "who is on duty now" (full rules = spec/002)
│   ├── notifications/       # Resend email dispatch + attempt recording (FR-009/FR-010)
│   ├── shared/              # env loading, error shape, Prisma client
│   ├── app.ts               # Express app wiring (routes + middleware)
│   └── server.ts            # bootstrap
├── tests/
│   ├── contract/            # Supertest API contract tests — one suite per FR group
│   └── integration/         # lifecycle walk-through tests (create→assign→ack→resolve)
├── .env.example             # every variable the app needs, placeholder values
└── package.json

frontend/
├── src/
│   ├── components/          # shared UI pieces (status badge, severity badge, forms)
│   ├── pages/               # Login, Events list, Event detail, Create event, First-password
│   ├── services/            # API client — typed ONLY from shared/ types
│   ├── App.tsx
│   └── main.tsx
├── tests/                   # component + basic render tests
└── package.json

shared/
└── types/
    ├── src/
    │   ├── user.ts          # Role, UserDTO (id/name/role only — no email, FR-018)
    │   ├── event.ts         # Severity, EventStatus, EventDTO, EventDetailDTO, HistoryDTO
    │   ├── auth.ts          # Login request/response, password-change payloads
    │   └── api.ts           # error shape, list envelopes
    └── package.json         # consumed by BOTH backend and frontend (Constitution III)
```

**Structure Decision**: Web-application monorepo with npm workspaces — `backend/`
(Express + Prisma API), `frontend/` (React SPA), `shared/` (contract types used by
both sides, satisfying the e2e-types principle without new tooling). Mirrors the
course's stated backend/frontend/shared-contracts layout.
